# 桌宠调优

> 状态：**占位文档**。本目录目前只有指令骨架，检查清单与示例项目待补；迁入实现前只提供流程指导，不产出可运行改动。

目标：在不改变桌宠原有性格与视觉风格的前提下，做出**可运行、可验证**的优化。

## 输入与默认值

- **项目路径与技术栈**（必需）：语言、框架、构建与启动命令。
- **优化目标**（缺省按「流畅度」处理）：卡顿/帧率、内存与 CPU、动画表现、交互反馈、素材体积。
- **约束**（缺省不改动）：不可改的角色设定、资源文件、目标平台与最低系统版本。

已知信息不要重复询问；用户没说技术栈时先读项目配置自行判断。

## 优化维度

1. 性能：主循环与定时器、重绘范围、图片解码与缓存、常驻内存。
2. 动画：帧数、帧率、补间与状态机，避免每帧重建对象。
3. 交互：点击/拖拽命中区域、反馈延迟、状态切换的一致性。
4. 素材：分辨率、格式、按需加载与打包体积。

## 流程

1. 先跑通原项目并记录基线（启动命令、帧率或 CPU/内存占用、一段录屏或截图）。
2. 按 [references/checklist.md](references/checklist.md) 逐项排查，只挑影响最大的 1–3 项动手。
3. 小步修改，每步都能运行；不擅自替换角色素材或重写架构。
4. 复测同样的基线指标，产出优化前/后对比与改动清单。
5. 无法量化时如实说明，并给出可手动验证的步骤。

## 交付物

- 修改说明：改了哪些文件、为什么、预期影响。
- 前后对比：指标表格 + 截图或录屏（放 `examples/`，大文件不提交）。
- 剩余问题与后续可选项。

## 关键约束

- 不改变角色性格、外观风格与用户已有配置；破坏性改动必须先征求意见。
- 不把「用了某个库」当作优化，优化必须落到可复测的指标或体验上。
- 第三方素材（立绘、音效、字体）需确认许可；不提交来源不明的资源。
- 指令中不写本机绝对路径，路径一律相对项目根目录。
